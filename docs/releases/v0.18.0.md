# autonome-pi v0.18.0

## Highlights

- New hosted background agents use durable main-agent progress reviews instead of an implicit wall-clock kill deadline. The default review interval is ten minutes; timers request inspection and never infer stalls, kill agents, retry phases, or launch successors. Explicit deadlines, foreground bounds, shell bounds, and cancellation remain authoritative.
- Verified session-owned workflows can be supervised across tool-specified working directories, with authoritative launch-cwd consistency checks. Reviews defer while the main agent is busy, acknowledge on the active branch, and disappear when completion or cancellation supersedes them.
- The workflow monitor presents one updating command row per observed lifecycle, grouped by phase or fanout item. Expand rows for bounded arguments, output, errors, and history; terminal details remain available. Argument completion is no longer displayed as successful execution.
- Command ingestion preserves real execution events, UTF-8 stream boundaries, and invocation/turn/occurrence/item identity. Ambiguous identities degrade to unknown rather than being guessed. Retained command data, identifier sizes, and correlation maps are bounded.
- Token displays lead with output and explicitly label totals as cumulative processed tokens. Cache reads are repeated input traffic, not unique context; reasoning is included in output. Canonical and ambiguous legacy fallback accounting remain distinct.
- Workflow recovery, checkpoint provenance, cancellation, continuation delivery, artifact safety, and compact per-workflow footer glyphs include the reliability improvements developed since v0.17.1.
- Includes the upstream `fast-uri` dependency override and lockfile update excluding versions below 3.1.6.

## Compatibility and upgrade

Fully restart Pi after updating. `/reload` alone does not refresh the entire native module graph.

The public declarative workflow contract is reduced and strict. Use flat `dynamic_workflow` arguments and bounded `attempts`; obsolete metadata, descriptive fields, and configurable retry knobs are rejected. Trusted historical v1 decoding remains internal. See [dynamic workflow documentation](../../dynamic-thread-phase-workflow/README.md).

`scripted_workflow` replaces the public `dynamic_workflow_harness` tool. Use exactly one of `script`, `scriptFile`, or a saved `.mjs` template, with explicit `permissions: "rwx"`. Migrate old `harness`/`harnessFile` fields accordingly.

`PI_THREAD_PHASE_SUPERVISION_CHECK_MS=1200000` selects a twenty-minute cadence for new schedules. Existing durable schedules preserve their chosen cadence across restarts. Historical/unmarked runs retain their previous bounded execution policy.

## Limits

- Delivery is durable and deduplicated, but at-least-once rather than exactly-once.
- Command previews can omit or truncate data, and credential redaction is best-effort. Missing execution evidence does not imply success.
- Live TUI behavior still benefits from a post-upgrade check in the user's terminal; automated component and lifecycle tests are not a claim of that manual check.
- This release does not activate the paused orphaned-successor repair backend or redesign mission workflows. The opt-in successor-v2 foundation is separate from the normal runner launch path.

See [supervision policy](../workflow-supervision.md) and [command ledger controls and limits](../command-ledger-ui.md).
