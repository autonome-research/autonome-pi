# v0.18.3 — reliable session-scoped terminal handoffs

## Changes

- Terminal handoffs now have deterministic session/run identities and reconcile against persisted, session-wide receipts, including other branches and legacy markers. Receipt eviction does not authorize replay.
- The v4 continuation store distinguishes unsent, submitted and unknown delivery. Submission intent is persisted before calling Pi; uncertain acceptance is held rather than blindly retried. Rejected explicit resends preserve prior uncertainty.
- Results older than the default 30-minute freshness window remain durable for explicit `/workflow-handoff <runId>` delivery. Dashboard `r` prepares that command without starting a model turn. Uncertain resends require confirmation.
- Completion cards explicitly use `triggerTurn: false`; duplicate terminal envelopes are deduplicated per run. Formatting errors no longer wedge the delivery queue. Dashboard annotations use a bounded refresh cadence and tolerate unreadable state; held backlog no longer causes repeated persistence churn.
- Hosted TUI/RPC background reviews and explorations explicitly opt into terminal success/failure handoffs. Foreground calls, bare CLI defaults, unattended hooks and print/JSON workers remain notification-only. Cancellation, session ownership and committed-successor suppression remain enforced; failure handoffs do not authorize recovery work.
- Both CLIs parse background environment markers with the existing boolean parser, consistently across validation, detachment and trigger labels. Values such as `0` and `false` no longer act as worker markers.
- Hosted test fixtures clean up their temporary repositories, projects and stores, including failed test runs.

Periodic main-agent progress prompts remain retired. There is no new polling agent or automatic recovery policy. The Pi submission API and continuation store are not transactional; this release does not claim exactly-once transport.

## Upgrade

```sh
pi install git:git@github.com:autonome-research/autonome-pi@v0.18.3
```

Replace the older configured package source rather than loading both copies. Back up continuation state and fully restart every Pi host using that store. The authoritative continuation schema is now `thread-phase-continuations/v4`; v2/v3 and legacy state are read compatibly, with uncertain pending work held rather than presumed unsent. Do not mix old/new hosts or downgrade without a backup and deliberate migration. The package update does not restart existing hosts automatically.

The retired `progress-reviews.json` remains untouched and inert. No `pi-durable` integration, public recursive-v3 activation, dependency update or archived successor-repair restoration is included.

## Validation and limits

Final intended validation uses isolated homes/stores/sessions and network-blocked deterministic fixtures:

- Complete visualizer suite: **328 passed, 0 failed**.
- Related dynamic workflow and terminal-title suites: **55 passed, 2 skipped, 0 failed**. Skips are legacy Pi v0.85.1 loader/PTY checks, not Pi 1.0.4 handoff checks.
- Combined: **383 passed, 2 skipped, 0 failed**.
- The background-marker regressions reproduced **8 failures before the fix**. They cover both CLIs with empty, `0`, `false` and `1` markers, including child PID ownership and prevention of recursive relaunch.
- Actual Pi 1.0.4 SDK lifecycle checks use synthetic local model streams. They cover busy/idle delivery, cards without extra turns, receipt reconciliation, restart/branch history, held backlog, owner mismatch and cancellation. These are not live-provider equivalence proof.
- One real session-hosted background code review on the installed candidate delivered both its completion card and marked continuation to the owning conversation. This establishes that observed path, not multi-host or exactly-once guarantees.
- Independent review identified the background-marker bug; it was fixed with red/green regression evidence. No subsequent independent approval of that repair is claimed.

A competing-resume test had an over-specific rejection-message assertion: the unchanged legacy exclusive-create writer can expose an empty or growing reservation to a contender. Deterministic probes reproduced both rejection variants on the committed baseline and candidate while retaining one winning successor. The test now accepts those specific fail-closed errors and additionally verifies the committed winner and absence of a losing run. Production reservation semantics were not changed.

A clean full-package `npm test` is **not** claimed. The previously recorded full-dynamic deadline timing failure and smoke-test external timeout remain open; this release's related-suite pass does not close them. Dependencies are unchanged, including the previously identified `fast-uri@3.1.7` advisory (GHSA-hrr3-gc8f-f4qj); the scratch-validated 3.1.8 update remains a follow-up.
