# v0.19.0 — fewer extensions, Pi 1.0.4 alignment

## Changes

- Removed the mission workflow extension, mission skill, prompts, active mission design docs and mission-only dependency `@autonome-research/fleet-router`.
- Removed the `/detach` tmux handoff extension. Generic subprocess detachment, background workflows, process-group cancellation and terminal handoffs remain supported.
- Five extensions remain: visualizer, optional terminal title, codebase exploration, code review and dynamic workflows.
- Patched `fast-uri` from 3.1.7 to 3.1.8, addressing GHSA-hrr3-gc8f-f4qj. The override excludes vulnerable 3.1.x versions; production `thread-phase` remains 6.1.0.
- Pinned the development Pi SDK to 1.0.4. Loader and explicitly enabled PTY checks target that version, and supplied missing or mismatched SDK paths fail instead of silently falling back.
- Custom dashboard UI is now restricted to TUI mode. RPC/print/JSON entry points receive an explanatory notification instead of attempting unavailable custom UI.
- Repaired deadline-sensitive test fixtures with realistic startup budgets and durable ordering/deadline assertions. Production timeout behavior is unchanged. Hosted wrapper fixtures now emit session startup and work in source snapshots without `.git`.
- Clarified recursive-v3 implementation, historical evidence and qualification limits without enabling recursion.

## Upgrade and removals

```sh
pi install git:git@github.com:autonome-research/autonome-pi@v0.19.0
```

Replace the older configured package source rather than loading both copies. Update dependencies as well as source, then fully restart Pi; `/reload` neither installs dependencies nor updates a checkout. When an existing live checkout shares dependency symlinks with development, prepare an independently installed candidate rather than mutating those shared targets.

Mission registries, plans, worktrees, sessions, logs, artifacts and saved detach state outside tracked package source are preserved. Historical release notes remain unchanged. There is no replacement mission framework or `/detach` command.

Back up the current profile and continuation state before switching. Continuation schema remains `thread-phase-continuations/v4`, introduced in v0.18.3. Do not mix pre-v4 hosts with that store or downgrade without a deliberate migration. Keep the previous installation available for rollback; updating configuration does not restart existing hosts.

## Validation and limits

The implementation gate used a fresh physical source snapshot and independent `npm ci --ignore-scripts`, with exact installed dependency versions and source identity checked before and after validation:

- Dynamic workflows: **460 passed, 44 skipped, 0 failed**.
- Visualizer: **329 passed, 0 failed**.
- Terminal title: **12 passed, 0 skipped, 0 failed**, including actual Pi 1.0.4 loader and explicitly enabled PTY checks.
- Total: **801 passed, 44 skipped, 0 failed**; separate removal/five-extension load and smoke checks also passed.
- Fresh production dependency audit: zero findings at validation time; installed `fast-uri` was 3.1.8 and SDK was 1.0.4.

Those are recorded implementation-gate results, not a claim that skipped recursive fixtures passed. Tests used isolated HOME/agent/store/session directories and a network-denial preload; that preload is not an OS sandbox. The earlier full-dynamic timing failures were addressed in fixtures. Removing mission coverage substantially reduced smoke duration, but the historical external smoke timeout cannot be conclusively reconstructed without its missing original logs.

Recursive-v3 stays **disabled by default**. Its SDK allowlist excludes 1.0.4, and a statically confirmed worker-bash result-contract mismatch remains unfixed in this release. Existing historical/synthetic fixtures do not qualify the current production worker profile or real provider/OAuth behavior. See [recursive delegation](../recursive-delegation.md). The hosted launch flag is an enablement control, not hostile same-user process containment.

Periodic main-agent prompts remain retired. No automatic recovery policy, public recursive activation, `pi-durable` integration or archived successor-repair restoration is included.
