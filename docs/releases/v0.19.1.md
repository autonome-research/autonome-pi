# v0.19.1 — recursive bash contract repair and offline qualification

## Changes

- The recursive runtime's node shell handle now preserves the scoped executor's real exit code. Previously it dropped that field, causing the bridge/worker adapter to reject ordinary completed commands.
- The bridge emits a command result only for integer exit codes. Timeout, cancellation, signal and spawn-error outcomes remain fail-closed rather than receiving fabricated success codes. Ownership, process draining and durable outcome classifications are unchanged.
- Added an offline integration regression through the real runtime handle, bridge and bash adapter. A separate Pi 1.0.4 scratch-candidate test exercises the actual SDK bash tool, including zero and nonzero exits. Exit 3 remains an error-flagged SDK tool result and taints node settlement to failed/`NONZERO`, preserving existing semantics.
- Auth and v3 execution fixtures now select an explicit SDK lane and reject missing requested versions or version mismatches. Historical CLI fixture lanes remain separate.
- Added controlled Pi 1.0.4 qualification for synthetic credential selection/refresh persistence, isolated resources and tool registration, compaction accounting, and connected recursive execution/joins/cancellation. Updated documentation distinguishes released behavior, fixture evidence and remaining qualification limits.

## Production gates remain unchanged

Recursive-v3 remains **disabled by default**, and the production SDK worker still admits only **0.86.0, 0.85.1 and 0.84.2**. It rejects 1.0.4 with `UNSUPPORTED_VERSION`.

Positive Pi 1.0.4 results came from separately installed physical scratch candidates whose only production-code deviation was an explicit 1.0.4 admission-list entry. That entry is **not included in this release**. Synthetic provider/auth tests do not establish live-provider transport, real OAuth behavior or production readiness. No public activation, live-provider qualification, automatic recovery policy or periodic supervision is added.

The command-result wire still forwards bounded stdout only; stderr remains at the runner. Abnormal shell outcomes surface as tool errors while the journal retains their classifications. This release does not introduce a new result protocol.

## Recorded implementation validation

- Baseline regression reproduced the dropped exit-code failure; the repaired real-handle/bridge test passed.
- Full default dynamic suite: **463 passed, 51 skipped, 0 failed**. Skips are not passing qualification cases.
- Scratch Pi 1.0.4 SDK/v3 suite: **11 passed, 0 skipped, 0 failed**, including actual SDK bash behavior.
- Scratch qualification suite: **7 passed, 4 skipped, 0 failed**; unchanged-admission qualification: **4 passed, 7 skipped, 0 failed**.
- Independent read-only review found **low risk, no critical findings and no required follow-up patch**. The earlier closeout orchestration timed out after producing test evidence; the independent review completed in a separately authorized recovery. The timeout was not relabelled as workflow success.

Tests used isolated HOME/agent/session/store/temp directories, independently installed dependencies, synthetic credentials and network-denial preloads. The preload is not an OS sandbox. Source hashes bind results to the tested trees. The release gate additionally checks the complete default dynamic, visualizer and terminal-title suites, explicit Pi 1.0.4 loader/PTY checks, removal/load checks, smoke and production dependency audit. Live-provider/OAuth work remains deferred.

## Upgrade

```sh
pi install git:git@github.com:autonome-research/autonome-pi@v0.19.1
```

Replace the older configured source rather than loading both copies, and fully restart Pi after updating the installation. Publishing this tag does not update an existing local-path package. Dependencies and continuation schema are unchanged from v0.19.0; preserve rollback state and do not mutate dependency targets shared with another running checkout.
