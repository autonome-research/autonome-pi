# v0.19.2 — coalesced workflow completion handoffs

## Fix

Previously, a completion card could enter an active conversation, allowing the assistant to inspect the results and finish its answer, while the separate marked handoff waited for idle. That delayed handoff then requested a redundant follow-up response.

Busy completions now stay durably unsent until Pi's native `turn_end` boundary, after the entire tool batch. The shared delivery path rechecks ownership, terminal evidence, freshness, cancellation, successor state and claim identity before returning a marked context entry. Pi combines its continuation with the next natural tool-loop request instead of waiting until the answer is over.

- Nothing is placed early into an opaque steering queue where it could become stale or cancelled before consumption.
- Earlier extensions' boundary entries and continuation decisions are preserved when composing the handoff.
- Idle completions still produce one intentional marked user-message wake-up. Completion cards remain non-triggering, though their content still enters the conversation.
- Submission intent precedes SDK acceptance; persisted session-wide receipts remain authoritative. Failed boundary persistence stays uncertain across settlement/reload and is not automatically retried.
- Stable delivery IDs, stale/manual handoffs, cancellation/successor suppression and the v4 continuation schema are unchanged. No periodic supervision, automatic workflow recovery or new dependencies are introduced.

A completion arriving after an answer has already been generated can still legitimately require another request. This fixes the avoidable busy-session delay, not arbitrary semantic duplication or exactly-once external effects.

## Validation

- Pi **1.0.4** is the tested host baseline. Eight actual-SDK, synthetic-provider regressions cover busy tool batches, multiple completions, expiry, cancellation, committed successors, persistence uncertainty/reload and composition with other extensions.
- Reviewed implementation: **812 passed, 51 skipped, 0 failed** across dynamic, visualizer and title suites. Skips are not passing qualification cases. Real Pi 1.0.4 loader/PTY, removal/load and smoke checks passed.
- Independent review found and reproduced a boundary-entry composition defect; it was fixed and regression-tested. The closing review reported low risk and no critical findings.
- An independently installed local canary passed **22 deployment tests**, load/smoke checks and a clean production audit. After a full host restart, live shell-only probes confirmed one busy boundary handoff before the next response, one intentional idle wake-up, and no handoff after cancellation. This is scoped local evidence, not a universal behavior guarantee.
- Prepublication validation separately repeats the full suites and package/load checks in a fresh physical snapshot with independently installed dependencies and a production audit. Tests isolate HOME, agent/session/store/temp paths and use finite synthetic providers; network-denial preloads are not OS sandboxes.

Recursive delegation remains disabled by default. Production worker SDK admission still excludes Pi 1.0.4; live-provider/OAuth recursive qualification and activation are not part of this release.

## Upgrade

```sh
pi install git:git@github.com:autonome-research/autonome-pi@v0.19.2
```

Replace the older configured package source rather than loading both copies, update dependencies in an independent installation, and **fully restart Pi**. `/reload` does not install the upgrade. Publishing the tag does not update a local-path installation or replace a running canary.

Preserve the previous installation for rollback. Do not restore stale continuation/session snapshots: they can replay messages already accepted. Do not mutate dependency targets shared with a running checkout. Historical user data, missions/detach data and previous releases remain untouched.
