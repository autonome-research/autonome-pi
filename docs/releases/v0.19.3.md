# v0.19.3 — reliable workflow completion discovery

## Fixes

A background workflow could finish without waking its idle owning chat when its terminal event was buried by another producer's event burst or filesystem notifications were missed. These failure mechanisms were reproduced locally; long workflow runtime alone was not a freshness defect.

- Live discovery now follows an index byte cursor rather than a sliding recent-event window. Each refresh reads at most **5,000 records / 8 MiB**; remaining events drain on later refreshes. Partial trailing records wait for completion, and file replacement or detectable truncation resets the cursor.
- Filesystem notifications are a latency hint, backed by **passive reconciliation every 5 seconds by default**, independent of footer/status-bridge availability. Watch installation failures and runtime watcher errors do not disable polling. This is store reconciliation, not periodic model supervision.
- Unreadable neighboring runs no longer block healthy completions. Unresolved discovery hints retry round-robin, up to 100 per refresh, without granting ownership or delivery authority.
- Polling preserves the single-flight submission barrier during asynchronous SDK prompt preparation, when Pi can still report idle. Only persisted acceptance or actual lifecycle settlement releases an unaccepted in-flight submission; uncertain submissions are not automatically replayed.

The v0.19.2 native busy-turn handoff remains intact. Fresh background success/failure returns control to its owning chat; cancellation and committed successors suppress continuation. Ownership, genuine terminal evidence, freshness, exact claim identity, intent-before-send and session-wide receipts remain authoritative. A run started hours ago can have a fresh terminal result; the default 30-minute freshness window is measured from completion, not launch.

No dependencies, continuation schema or recursive admission policy changed. No automatic workflow recovery/resume, periodic model check-ins, missions or `/detach` were introduced. Recursive delegation remains disabled by default, and production worker SDK admission still excludes Pi 1.0.4.

## Validation

- Reviewed implementation on Pi **1.0.4**: **826 passed, 51 skipped, 0 failed** across dynamic, visualizer and title suites. The 51 gated dynamic skips are not passes or recursive qualification. Real SDK handoff lanes, loader/PTY, removal/load and smoke checks passed.
- Fourteen additional regression tests cover long-start/fresh-end success and failure, event bursts, lost notifications, watcher failures, idle batch/preflight ordering, unreadable-run recovery, lease/receipt safeguards, discarded boundary drafts, virtual 35-minute idle lifetime and bounded cursor behavior.
- Independent adversarial review found a new submission race plus watch-installation and unreadable-neighbor failures. One repair pass addressed them; an independent closing review **ACCEPTed** the frozen candidate after executing 76 overlapping checks. Parent verification separately reran 21 focused checks. These counts are not additive unique-test totals.
- Fresh independently installed canary: **363 deployment tests passed, zero skipped/failed**, with load/smoke checks and a clean production audit. After a full host restart, finite shell-only live probes confirmed one native busy handoff, one intentional idle wake-up and no cancellation handoff, corroborated by persisted receipts.
- A real **47-minute** investigation workflow also woke the idle foreground, but ran on the previous v0.19.2-equivalent installation. It is not a wall-clock soak of this release. Candidate long-lifetime tests use old timestamps and virtual time; no new >=35-minute live soak is claimed.
- A separate prepublication gate repeats the full suites, load/smoke checks and production audit in a fresh physical snapshot with independent dependencies. Tests isolate HOME, agent/session/store/temp paths and use finite synthetic providers; network-denial preloads are not OS sandboxes.

## Remaining limits

The reported other-machine failure was not directly diagnosed: no affected remote run or environment was supplied. Local reproductions establish concrete fixes, not universal platform behavior.

Startup recovery remains bounded to recent history plus durable pending records. Runtime retry hints are not a durable outbox; never-observed terminals outside that startup window can still be missed after restart. Sustained input beyond bounded drain capacity, globally unreadable/corrupt index state, arbitrary same-inode truncate/regrow and nonlocal filesystem behavior are not comprehensively qualified. Missing persisted acceptance never authorizes blind replay; no semantic exactly-once guarantee is made.

## Upgrade

```sh
pi install git:git@github.com:autonome-research/autonome-pi@v0.19.3
```

Replace the older configured package source rather than loading both copies, install dependencies independently, and **fully restart Pi**. Native store imports changed; `/reload` is not the acceptance procedure. Publishing the tag does not update a local-path installation or replace a running canary.

Keep the previous installation for rollback and preserve current user data. Do not mutate shared dependency targets or restore stale session/continuation snapshots, which can replay previously accepted messages. Historical release tags and notes remain unchanged.
